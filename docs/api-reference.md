# API reference

Base path: `/api/`. Authentication: JWT (`Authorization: Bearer <access_token>`,
`rest_framework_simplejwt`, `ACCESS_TOKEN_LIFETIME=30min`,
`REFRESH_TOKEN_LIFETIME=7 days`, `ROTATE_REFRESH_TOKENS=True`). Default permission
for any endpoint not listed otherwise is `IsAuthenticated`
(`REST_FRAMEWORK['DEFAULT_PERMISSION_CLASSES']` in `config/settings.py`).

This is a hand-written mirror of the real endpoint surface, generated by reading
`apps/*/urls.py`, `apps/*/views.py`, `apps/*/serializers.py`. The authoritative,
always-up-to-date version is the generated OpenAPI schema —
**regenerate this file whenever an endpoint changes** (see
`docs/architecture.md`'s Maintainability note):

```bash
cd backend && .venv/bin/python manage.py spectacular --file /tmp/winchicken-schema-check.yaml
```

Payload examples below are pulled from the implementation-detail spec's section 11
where the endpoint matches (weekly KPI, finance summary, expense categories, batch
close), and otherwise constructed directly from the real serializer fields — no
field name below is invented.

## Meta

| Method | Path | Auth | Permission |
|---|---|---|---|
| GET | `/api/health/` | none | `AllowAny` — Docker healthcheck, not in the cahier des charges endpoint list |
| GET | `/api/schema/` | JWT | `IsAuthenticated` (default) — raw OpenAPI document |
| GET | `/api/docs/` | JWT | `IsAuthenticated` (default) — Swagger UI |

```json
// GET /api/health/ -> 200
{"status": "ok"}
```

## apps.protocols

| Method | Path | Auth | Permission |
|---|---|---|---|
| POST | `/api/protocols/onboarding/` | JWT | `IsAuthenticated` |

```json
// POST /api/protocols/onboarding/
{
  "house": {"name": "House A", "sizeM2": 400, "maxCapacity": 5000},
  "batch": {"initialCount": 5000, "startDate": "2026-08-25", "productionType": "BROILER", "breed": "Ross 308", "growthCycleValue": 8, "growthCycleUnit": "WEEK"},
  "protocolLines": [
    {"category": "FEEDING", "from_value": 1, "from_unit": "DAY", "to_value": 15, "to_unit": "DAY", "until_end": false, "what": "Starter feed", "details": "3000 kcal, 22.5% protein"}
  ]
}
// -> 201
{
  "house": {"houseCode": "H-1-001", "name": "House A"},
  "batch": {"batchCode": "BATCH-2026-001"},
  "protocolLines": [{"id": 1, "category": "FEEDING", "from_value": 1, "from_unit": "DAY", "to_value": 15, "to_unit": "DAY", "until_end": false, "what": "Starter feed", "details": "3000 kcal, 22.5% protein"}]
}
```

`batch` is optional — omit `initialCount` to create the house (and its protocol
lines) without starting a batch yet (`"batch": null` in the response).

```json
{"rule_type": "LOW_STOCK", "preferred_channel": "SMS", "active": true}
```

Every `List*View` in this project except `FinanceTransactionsView` uses the
project-wide default pagination (`PageNumberPagination`, `PAGE_SIZE=20`,
`?page=`), so most `GET` list responses are wrapped in
`{"count", "next", "previous", "results"}` — `FinanceTransactionsView` is the one
exception, with its own hand-rolled `{"count", "page", "pageSize", "results"}` shape
(see `apps/finance/views.py`).
